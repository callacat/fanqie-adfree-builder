# 方案：破解版 APK 改造（去后门/去广告/去弹窗）

> 2026-09-11 东哥拍板：官方直改路线搁置，转破解版底包改造；上 loop 方式让码农处理。
> 本文档 = 唯一事实源（K5/I9），派单只发指针。

## 1. 路线原理（为什么换底包）

破解版结构（9-7 老马拆解实锤）：
- 外层 = Tinker 壳（MuteApplicationStub → MuteApplication，22 dex 重打包业务码 + Tinker loader）
- `assets/liborgapk.so` = 官方 73368 原包 ZIP（**签名未动**，证书与官方完全一致）
- 运行时：壳 attachBaseContext → 验 config → 反射实例化官方 MainApplication，sourceDir 重定向到官方原包

**核心优势**：服务端 sig_hash=证书指纹，APK 本体（含签名块）始终官方 → 设备注册不异常。
此前 b3-shell 三层签名伪装（v22-v35）卡的正是这一层；破解版天然绕过，**改造只动外层 dex，不碰 liborgapk.so** → 签名机制零影响。

## 2. 改动点分类框架（老马判定，码农机械执行）

| 类 | 定义 | 处置 |
|---|---|---|
| A | Tinker 壳机制（Mute* loader/stub/config 校验） | 保留 |
| B | 去广告/去弹窗/去验证 patch（对应 FanqieHook 点位、资源 patch） | 保留，核对是否干净 |
| C | 可疑行为（后门候选：非官方域名外传、动态 dex/so 加载、敏感 API、签名/风控对抗以外的隐藏逻辑） | **去除（NOP/移除）** |
| D | VIP 伪造/SVIP 解锁 UI | 默认保留（东哥清单未含） |

判定权在老马（硬规则1：构建方不做逆向定位）；码农只产出事实 diff。

## 3. 分段推进（loop 闭环）

**round16a（反编译 diff，码农 CI）**：
- apktool d / baksmali 解外层 22 dex + 官方原包（`crack/inner-orgapk.zip`，同 Release samples `inner-73368-orig.apk`）
- 逐 dex 对比：新增类/修改方法/删除方法，机械归档
- 产物：`docs/diff-report.md`（dex 级统计表 + 差异清单索引）+ `docs/diff-baksmali/`（差异方法 baksmali 全文）
- 附：体积构成审计（外层 ~100MB 构成：资源副本/so/dex 各占多少）

**老马审读**：diff 报告 → A/B/C/D 分类 → 写点位蓝图（修复蓝图-破解版改造.md）

**round16b（patch 构建码农 CI）**：按蓝图 NOP/移除 C 类点 → 重打包（外层结构不变）→ 签名 → Release

**装机三测（老马，PJD110/ACE5）**：安装/启动/进书城/进阅读页 + logcat 审计面核对 + 对照破解版原包行为

## 4. 后门审计验收标准（「不可证明不存在」改为「核查面清单」）

1. **全量 diff 闭环**：外层 dex vs 官方 = A+B(+D) 类改动点，无无法归类的残留差异
2. **网络出口审计**：外层代码网络请求全部指向官方域名或无网络行为
3. **动态加载审计**：无运行时下载/加载外部 dex/so 路径
4. **敏感 API 审计**：无短信/联系人/位置/录音等官方功能之外的调用
5. **可复现性**：round16b 产物从蓝图点位可复现构建，不依赖原破解包黑盒

交付时明示「已核查面」与「不可证明面」（如 native so 层仅做 hash/来源核对，不反编译深审——除非后续派单）。

## 6. 风险与红线

- 破解版可能随服务端策略升级失效（mod 典型死法）——改造版同样暴露于此，非本次可解
- 外层壳的 config 校验（KVManager/patch version）若带远端开关，审计时重点核对（C 类候选）
- 法律红线：仅供东哥本地个人研究，不分发；版权物不入库（.gitignore 兜底）
- 对照实验三包法照旧：官方原版/破解版原包/改造版 三方对照，官方原版异常=设备指纹问题先停
