# 「当前版本不安全」弹窗修复蓝图（round4 静态实锤 + 修复方案）

> 作者：老马 2026-09-07 上午。基于 fanqie-73532-adfree-signed.apk（= 官方 73532 + 去广告 patch + 换签）静态逆向实锤。
> 调研参考：research-round4-unsafe-prompt.md（gpt-5.6-luna 联网调研：正版用户也遇过此弹窗；FanqieHook 运行时 hook 不触发 → 指向服务端风控，非本地签名自检）。

## 1. 机制结论（静态证据链，已实锤）

「当前版本不安全，请到正规应用市场下载」= **服务端返回业务 code=110 时客户端弹的 Toast**，与本地签名自检无关。

完整调用链（真机 APK 内反解）：

```
服务端 API 响应业务 code=110
  ↓
com.dragon.read.util.NetReqUtil.doAfterDeserialization(String,Throwable,I,Object,List)   [classes21.dex]
  analyseCode() = 110 分支：
    [43] const/16 v0, 110
    [44] NsBaseNetworkDependImpl.INSTANCE.assertIllegalAccess()
  ↓ (Kotlin delegate)
com.dragon.read.base.depend.NsBaseNetworkDependImpl.assertIllegalAccess()                 [classes21.dex]
  iget-object $$delegate_0 → invoke-interface assertIllegalAccess
  ↓ (真身)
com.dragon.read.component.base.NsBaseNetworkDependImpl.assertIllegalAccess()              [classes2.dex]
  const v0, 2131104221 (0x7f0611dd = @string/cjw = "当前版本不安全，请到正规应用市场下载")
  ToastUtils.showCommonToastSafely(0x7f0611dd, 1)
```

旁证：
- 资源 `0x7f0611dd` = `string/cjw` =「当前版本不安全，请到正规应用市场下载」（ARSC 自解，唯一不安全文案条目；classes7.dex 另有短文案「当前版本不安全」字符串未定位到调用，暂不动）。
- 同文件 `NsBaseNetworkDependImpl.doAfterDeserialization`（classes2，组件层，网络栈不同实例）还有一套 **服务端封禁下发机制**：响应 code=100 且 message 非空 → gson 解析 `com.dragon.read.http.SvrBanApiModel`（字段 minBanTime/maxBanTime/banRate，单位秒，banRate 万分比）→ 按 API path 存入 `m95/d` ConcurrentHashMap 封禁表。**这套管「API 降级封禁」，与 110 弹窗是两条线，本轮不动它。**
- L1 审计：`getPackageInfo`/签名 API 调用全部在 SDK 命名空间（androidx/huawei/微信/QQ/tinker/mira/cmic），com.dragon.read 业务包内 0 处 —— 没有本地签名自检。
- Ace 启发：code=110 的语义在抖音系 = 「客户端版本非法/风险」。触发依据疑似签名证书指纹（服务端比对注册上传的证书）或请求签名（X-Argus 等），无法静态确认，**不需要确认即可 patch**（客户端只负责弹 toast）。

## 2. Patch 点位表（本轮全部 = 平话替换，风险低）

| # | 文件 | 类 | 方法 | 现状 | 改法 |
|---|---|---|---|---|---|
| P1 | classes2.dex | `Lcom/dragon/read/component/base/NsBaseNetworkDependImpl;` | `assertIllegalAccess()V` | const 0x7f0611dd + ToastUtils.showCommonToastSafely | 整体替换为 `return-void`（空方法） |
| P2 | classes21.dex | `Lcom/dragon/read/base/depend/NsBaseNetworkDependImpl;` | `assertIllegalAccess()V` | iget-object $$delegate_0 + invoke-interface | 整体替换为 `return-void`（双保险，防 delegate 指向别处） |
| P3 | classes21.dex | `Lcom/dragon/read/util/NetReqUtil;` | `doAfterDeserialization(...)V` @ instr [43-44] | `const/16 v0,110` + `if-ne v1,110` + invoke assertIllegalAccess | 把 `if-ne v1, 110 → assertIllegalAccess` 的调用 nop 掉（保留 analyseCode 调用，不破坏其余 code 分支），或把 [43] 的 `const/16 110` 改成不可能命中的值（如 0x7FFF） |

建议优先级：P1（治本，Toast 永不出来）→ P3（阻断调用点）→ P2（双保险）。P1+P3 即可，P2 可选。

smali 参考写法（P1，apktool d 后 smali_classes2/com/dragon/read/component/base/NsBaseNetworkDependImpl.smali）：

```smali
.method public assertIllegalAccess()V
    .locals 0
    return-void
.end method
```

注意：原方法 `.locals`/寄存器数可能非 0，直接整体替换方法体最稳；不要只删 const/Toast 行（会留死寄存器引用）。

## 3. 验证计划（老马负责，码农不用做）

1. 构建后 apktool d 反解新 APK → grep 确认 P1/P2/P3 三处已按蓝图落位（码农自证）。
2. 装机（ACE5 优先，CT107 备用）→ 打开番茄 → logcat 过滤 `ToastUtils|assertIllegalAccess|110` 观察。
3. 若弹窗消失 → 连续阅读 30 分钟复测广告去除效果 → 回报东哥。
4. 若弹窗仍在 → 说明还有第二条触发路径（如 classes7.dex 短文案「当前版本不安全」的独立调用），再深挖。

## 4. 风险与红线

- **法律红线不变**：仅供东哥本地个人研究，不分发。
- **不改 SvrBanApiModel/封禁表逻辑**：服务端可能对 110 客户端下发更重的处置（账号风控/内容封禁），patch 后只屏蔽提示，风险语义仍在。东哥真机使用时如遇功能受限/账号异常，立即回退原版观察。
- **服务端行为可能变化**：字节随时可能改 code 语义或增加新检测；本方案对 73532 静态结构有效，升级版本需重验。
- 需要真机重新安装覆盖（同签名 v3 包，保留数据）。
